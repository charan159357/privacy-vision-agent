# 🛡 Privacy Vision Agent — On-Device Visual Perception for Lightweight Browser Agents

A working prototype of a **privacy-preserving visual-perception agent**: a browser extension + local server where all sensitive understanding happens **on the device** (WebGPU/WASM), and only a *redacted* view of the page ever reaches the server.

Built for the SIH-style brief: *"build a privacy-preserving visual perception agent for lightweight browsers."*

---

## The idea in one diagram

```
┌─────────────────────────── user's device ───────────────────────────┐
│                                                                      │
│  page ──► ① DOM structure  ② YuNet face detection        ┌────────┐ │
│            (labels only)     (ONNX Runtime Web,          │ gateway │ │
│  page ──► ③ canvas snapshot  WebGPU → WASM, on-device)   │ fetch/  │ │
│            (never leaves)                                 │ XHR     │ │
│                     │       ④ redact: blur faces,        │ scrub   │ │
│                     ▼          black-out passwords,       └────┬───┘ │
│   sanitized pva/v1 payload  ───►  mask PII + pixel audit       │     │
│            (no values, no raw pixels)                          │     │
└────────────────────────────────┬────────────────────────────────┴─────┘
                                 ▼
        server (local or remote) — sees ONLY the sanitized context
        planner → { click, type, scroll, … }  (deterministic offline
        fallback, or OpenAI-compatible LLM/VLM when a key is set)
                                 │
                                 ▼
        agent executes commands locally → loop until task done
```

**Privacy invariants** (enforced, and proven by the harness):

1. Input **values** (typed passwords, Aadhaar numbers…) never enter the payload — the extractor only sends labels/placeholders.
2. The screenshot is **redacted before encoding** — faces blurred, passwords/OTP always solid-black, PII masked — with a byte-level audit.
3. A **Privacy Gateway** watches every `fetch`/`XHR` (including the page's own) and strips PII from outgoing bodies as defense in depth.
4. The server logs redaction **metadata only** (categories + counts + deltas), never content.

Two evaluation surfaces:

- **`harness/eval.js` (Node)** — deterministic, reproducible: 13 text-PII fixtures, 3 field-form fixtures, a synthetic 640×1100 banking screen drawn with node-canvas (pixel-level redaction proof, including an outside-leakage grid that accounts for the redactor's guard band), real YuNet inference via `onnxruntime-node`, and a live round-trip against the agent server (M5).
  ```bash
  cd harness && node eval.js        # or: scripts/dev.sh --eval
  ```
- **`/eval.html` (browser)** — the same metrics run live in-browser with the real WebGPU/WASM pipeline; press "Run evaluation".

### Metric definitions

| Metric | Formula |
|---|---|
| M1 (25%) | `0.5 · categoryAccuracy + 0.5 · redactionBoxRecall` against ground truth on the synthetic screen |
| M2 (20%) | `0.6 · text F1 + 0.4 · field F1` over 13 text fixtures + 3 form fixtures (decoy fields included) |
| M3 (20%) | `0.5 · boxPrecision + 0.5 · min(1, pixelsChangedInsideGT/0.95)`; leakage = pixels changed outside GT (GT boxes expanded 3px for the redactor's pad) must be **0** |
| M4 (20%) | mean of 5 subscores: model ≤1 MB, payload ≤300 KB, DOM analysis ≤50 ms, face inference ≤600 ms, total pipeline ≤1500 ms |
| M5 (15%) | `max(0, 1 − latency/8000)` for a full agent round-trip incl. done-detection |

### Server API

| Endpoint | Body | Response |
|---|---|---|
| `POST /api/agent` | `pva/v1` sanitized payload | `{ commands, step, done, mode, planMs, received }` |
| `POST /api/privacy-audit` | any JSON | `{ ok, leaks, verdict }` |
| `GET /api/health` | — | `{ ok, uptime, llmMode }` |

Commands are validated: allowed actions `click | type | clear | scroll | wait | read | open_url | done`; `uid` must exist in the sent elements; `type` ≤ 200 chars; ≤ 8 commands/step.

**LLM/VLM mode** (optional): set `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` and the planner switches from the offline fallback to an OpenAI-compatible chat endpoint that receives the sanitized payload (image + element map). Offline mode needs nothing.

### On-device vision (the "ViT-equivalent")

- **Face detection**: YuNet 2023mar (OpenCV Zoo) — 232 KB ONNX, ~21 ms WASM / WebGPU-first, runs via ONNX Runtime Web with WebGPU → WASM fallback.
- **PII detection**: layered, with confidence tiers —
  field type (.98) > autocomplete (.95) > label (.92) > hint (.88) > typed value (.90) > visible text (.86) > image alt (.78);
  regex `scanText` for Aadhaar / PAN / phone / email / credit card / account number / IFSC / DOB, with look-around word boundaries (16-digit card numbers are *not* Aadhaar).
- **Redaction**: passwords & OTP always solid; faces follow the face strategy (blur by default); everything else blur (box-blur, ≥6·radius) or solid. Every redacted region gets a rect + strategy recorded for the audit.
- **Audit**: `pixelDelta` (% pixels changed), `byteDelta`, `redactionCoverage`, payload size, per-category counts — all sent to the server as **metadata**.

## Browser extensions

The extensions are fully self-contained (engine + ONNX Runtime + YuNet model + wasm all vendored — zero CDN).

```bash
scripts/build-extensions.sh     # copies engine/vendor into both folders
```

- **Chrome (MV3)**: `chrome://extensions` → Developer mode → *Load unpacked* → `extension/chrome`.
- **Firefox (MV2)**: `about:debugging#/runtime/this-firefox` → *Load Temporary Add-on* → `extension/firefox/manifest.json`.

Open the banking demo (server running), click the 🛡 button on the page, press **▶ Start**. The popup shows live stats (faces redacted, PII types, pixel delta, gateway scrubs). Chrome additionally injects a **page-world gateway** so even the page's own traffic is scrubbed; Firefox does the same via `tabs.executeScript`.

## Notes & decisions

- **No CDNs anywhere**: `ort.all.min.js`, both wasm variants + JS wrappers, and `yunet.onnx` are served from `server/static/`.
- `numThreads=1` for wasm keeps the agent off cross-origin-isolation/SharedArrayBuffer requirements; WebGPU (jsep) is used automatically when available.
- The demos iframe the panel; the panel analyzes the **parent page** (extractor/renderer honor `opts.doc/opts.win`), which is exactly what the extension does in-page.
- Typing uses the element-realm prototype value setter + `input`/`change` events, so React-style pages and cross-iframe inputs update correctly.
- The fallback planner is intentionally deterministic for the demo tasks; swap `LLM_*` env vars for open-ended tasks.
